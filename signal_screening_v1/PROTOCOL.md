3. **问题 3**：只在问题 1 或 2 为阳性时进行（更长历史、成对关系），作为单独一轮，经用户复核后启动。

## 数据与任务

- 复用 `five_task_hgt_v1/data` 的合并对抗单元（只读）：训练 266 场，验证 57 场；测试集不读取。
- 任务只有 Player：在预测时刻**在场**的候选球员中预测下一执行者。合并对抗目标为双方各 0.5 的集合目标。
- 主评估：单人目标（非对抗），top-1、top-3、MRR 以及 NLL；对抗目标单独报告；另按"真实下一执行者上次出手距锚点多远"分组报告。

## 在场候选（只用预测时刻可知的信息）

- 时钟：period 内秒数，第二个半场加 2700 秒。
- 首发：一直是候选，直到被换下或被罚下。
- 替补：时钟达到 `(换人分钟 + 1) × 60` 秒后，或本人在锚点及之前已经出手，才成为候选。同一分钟内不提前纳入（用户指出：否则等于用赛后记录预知谁将上场）。
- 被换下：时钟达到 `(换人分钟 + 1) × 60` 秒后移出。
- 红牌：带 1701 或 1703 的犯规发生在锚点**之前**时移出。
- 真实下一执行者不在候选中时，记为"够不着"：top-k 计为未命中，不进入损失和 NLL，并报告数量。验证集单人目标中有 128 个（0.19%）。

## 模型（各条件共用的部分）

- **情境编码器：** 两层 Pre-LN 注意力，64 维、4 头，带 Δn、Δt 偏置；读出为锚点加窗口均值。输入为每个窗口单元的类型、子类型、period、时间、位置、合并对抗标记、参与方相对参照队的球队关系，以及在线控球阶段关系。M0–M3 的情境**不含任何球员身份**，也不含"是否为锚点执行者"。
- **M0_ctx_identity 的情境：** 在上述输入之外，每个窗口单元的 token 再加上其参与球员的静态表示（与候选侧共用同一个投影，即同一套球员嵌入；合并对抗两人相加）。这相当于把球员输入挂在事件下面的序列模型。
- **打分：** MLP([情境, 候选表示])，在在场候选之间做 softmax。

## 候选表示（逐级加入）

| 条件 | 内容 |
|---|---|
| M0_static | 全局球员 ID（训练词表）、角色、惯用脚、身高、体重、首发、与参照队同队 |
| M1_summary | M0 + 窗口内出手次数、距上次出手的单元数和秒数、窗口内未出现过、是否为锚点执行者 |
| M2_pooled | M1 + 候选人本人最近 32 个窗口单元的内容（类型、子类型、位置、合并标记、距锚点单元数和秒数、该单元的球队关系），取均值池化和最近一个事件，不依赖情境 |
| M2_shuffled | 同 M2，但历史内容换成同队另一名在场候选的（每个样本按固定种子重排）；M1 的特征保持真实 |
| M3_attention | M1 + 同样的历史，用"情境 + 静态候选"作查询，对本人事件做多头注意力 |
| M0_ctx_identity | 候选同 M0（只有静态表示）；情境中每个事件挂上参与球员的静态表示（见上） |

## 训练与判定

- AdamW，weight decay 1e-4，梯度裁剪 5，batch 256，每场每轮 Rotate 128 个目标，FP32，确定性设置。
- 学习率在 {9e-4, 2.7e-3, 8.1e-3} 中选择：M0 和 M3 各训练 24 轮（seed 20260715），取两者验证 NLL 均值最低者。
- 正式运行：5 个条件 × 3 个 seed，最多 120 轮，平台期衰减两次后停止；按验证 Player NLL（够得着的目标）选模。
- **阳性标准：** 单人 top-1 至少 +1.0 pp，或 NLL 至少 −0.03；3 个 seed 方向一致；按比赛聚类的 bootstrap 95% 区间不含 0。
- 验收：13 项测试，包括候选集合因果性（换人分钟、观测、红牌、未来扰动）、只有声明了的条件在情境中带身份（带身份时与逐单元慢速参照一致）、条件间信息隔离、历史位置与慢速参照一致、重排对照、目标权重与够不着计数（慢速参照）、模型掩码和保存加载、身份确实影响 M0_ctx_identity 的得分、原有 5 个条件与存档代码逐位一致、评分。

### 3a 窗口外的本场历史（05:49 启动，`configs/stage3a_match_history.json`，6 个运行）

- **参照：** 阶段 2 的 M2_pooled，不重跑。同代码、同日程、同 seed 可以逐位复现；报告会核对参照运行的协议版本、seed 和学习率。
- **H_match：** 在 M2 上做两处改变。
  - 摘要另加 3 个本场特征：到锚点为止的本场出手次数、距本场上次出手的单元数、本场尚未出手。窗口摘要保留，所以本场摘要是在其上追加的。
  - 历史改为本场到锚点为止最近 32 个出手单元，不限于 80 单元窗口。事件特征与 M2 相同，但"距锚点单元数 / 80"在 79/80 处截断；另加"在窗口外"和"log1p 距锚点单元数 / 8"两个特征。因此窗口内的历史与 M2 逐位相同（验收测试检查）。
- **H_match_shuffled：** 历史内容在同队在场候选之间整体交换，与 M2_shuffled 用同一种重排；摘要保持真实。
- **对照：** H_match − M2_pooled，以及 H_match − H_match_shuffled。
- **输出：** `runs_stage3a/`、`reports_stage3a/`。

### 3b 球员间关系（已实现并通过验收，等待用户确定基准条件）

- **转移：** 本场相邻两个单元中，从前一单元的每个参与者到后一单元的每个参与者各记一次，只计不同球员之间的转移。锚点到达后一单元时才计入，所以"锚点 → 目标单元"的转移不会被使用。
- **成对值**（对每个候选和另一名球员）：
  - 另一名球员 → 候选的次数（log1p）；
  - 候选 → 另一名球员的次数（log1p）；
  - 距最近一次"另一名球员 → 候选"的单元数（log1p / 8）；
  - 尚无此转移。
- **P_anchor：** 候选与锚点执行者的成对值。合并对抗的两名参与者，次数相加。
- **P_window：** P_anchor + 窗口内出过手的其他每名球员各一个关系 token，做均值池化。token 包括：该球员与候选的成对值、该球员在窗口内的出手次数、距其上次出手的单元数、是否为锚点执行者、是否与候选同队。
- **P_window_shuffled：** 全部成对输入在同队在场候选之间交换，与历史对照用同一个排列。
- 新增分支最后创建，输出层初始化为零，所以初始化时 P 条件的得分与其基准条件完全相同。
- **待定的基准：** 草案（用户批准的版本）写的是建在 M2 上，我建议改为建在 H_match 上。成对次数按整场计算，同时携带候选本人在本场的活跃度；以 H_match 为基准时，P − 基准衡量的是关系本身，而不是历史范围的扩大。用户确认之前不启动 3b。
